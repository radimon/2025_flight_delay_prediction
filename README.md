# ConvLSTM Mobility Smart Parking System

An intelligent parking guidance system that integrates spatiotemporal crowd-flow prediction, LLM-based natural-language parsing, and multi-criteria route optimization.

The system uses human mobility data to estimate parking availability probability without requiring real-time physical parking sensors, then generates ranked parking recommendations and fallback routes before departure.

The mobility prediction pipeline is built using the **City C dataset from the ACM SIGSPATIAL GIS Cup 2025 Human Mobility Prediction Challenge**.

---

## System Overview

The system adopts a dual-layer offline-online architecture.

### Offline Phase

1. Preprocess raw mobility trajectories into spatiotemporal grid-density data.
2. Construct temporal, calendar, and historical-prior features.
3. Train a ConvLSTM-based crowd-flow prediction model.
4. Convert predicted mobility demand into simulated parking availability.
5. Calibrate availability probability using historical/simulated parking observations.

### Online Phase

1. **Natural-Language Query Parsing**  
   OpenAI function calling extracts structured travel information such as origin, destination, date, and time from natural-language input.

2. **Geographic Retrieval**  
   Geographic services convert locations to coordinates and retrieve nearby candidate parking lots.

3. **Dynamic Prediction**  
   The ConvLSTM model estimates future mobility demand around candidate parking locations at the predicted arrival time.

4. **Parking Availability Estimation**  
   Predicted mobility demand is converted into parking availability probability.

5. **Multi-Criteria Scoring**  
   Candidate parking lots are ranked using availability probability and travel costs including walking distance, detour time, driving time, and parking-related cost.

6. **Fallback Routing**  
   Top-K parking candidates are chained into fallback options so that lower-ranked candidates can be used when the preferred parking lot is unavailable.

## Prediction Models

Five prediction models were evaluated during development:

| Model | Description |
| --- | --- |
| **ConvLSTM** | Primary model combining spatial neighborhood information with temporal dependencies |
| LightGBM | Gradient-boosting baseline with engineered temporal features |
| LSTM | Temporal recurrent baseline |
| GRU | Lightweight recurrent baseline |
| PredRNN | Spatiotemporal recurrent prediction model |

ConvLSTM was selected as the primary prediction model based on the experimental comparison.

### Experimental Results

The model comparison used in the project presentation produced the following test-set results:

| Model | RMSE | MAE | R² |
| --- | ---: | ---: | ---: |
| **ConvLSTM** | **1.922** | 1.215 | **0.716** |
| LightGBM | 1.928 | 1.211 | 0.714 |
| PredRNN | 1.928 | 1.214 | 0.714 |
| GRU | 1.953 | **1.208** | 0.706 |
| LSTM | 1.998 | 1.254 | 0.693 |

These values correspond to the experimental run used for the project report/presentation.

Retraining may produce slightly different numerical results because of stochastic model initialization, GPU operations, library versions, and other sources of nondeterminism.

### 1. Clone the repository

```bash

```

Upgrade pip:

```bash
python -m pip install --upgrade pip
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### GPU / CUDA

ConvLSTM training is computationally expensive. A CUDA-capable NVIDIA GPU is strongly recommended for full training.

Check whether PyTorch detects CUDA:

```bash
python -c "import torch; print('CUDA available:', torch.cuda.is_available()); print('CUDA version:', torch.version.cuda); print('Device:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

A GPU-enabled environment should report:

```text
CUDA available: True
```

If CUDA-enabled PyTorch must be installed separately, follow the installation instructions provided by PyTorch for the CUDA version supported by your system.

CPU execution is possible but ConvLSTM training can be substantially slower.

## Dataset

This project uses mobility data from the:

**ACM SIGSPATIAL GIS Cup 2025 — Human Mobility Prediction Challenge**

The challenge provides synthetic but realistic human-mobility trajectories across multiple anonymized cities over 75 days.

Official challenge website:

https://sigspatial2025.sigspatial.org/giscup/

Dataset:

https://zenodo.org/records/18050604

The GIS Cup organizers state that the dataset is now fully open and available for general use.

### City C

This project uses the **City C** mobility dataset.

The original City C data are renamed locally as:

```text
CityC_Sapporo.csv
```

This filename is used by the project pipeline for convenience.

After downloading and extracting the dataset, place the City C CSV at:

```text
data/raw/CityC_Sapporo.csv
```

The expected raw-data schema is:

```text
uid,d,t,x,y
```

where:

- `uid` — individual identifier
- `d` — day index
- `t` — time-slot index
- `x` — spatial grid x-coordinate
- `y` — spatial grid y-coordinate

Raw mobility data are **not included in this repository**.

# Reproducing the ConvLSTM Pipeline

The complete pipeline can be reproduced from the raw City C CSV.

## Step 1 — Prepare the Dataset

Make sure the raw file exists at:

```text
data/raw/CityC_Sapporo.csv
```

Then run:

```bash
python -m scripts.prepare_data
```

The script aggregates individual mobility records into a spatiotemporal density table and generates:

```text
data/processed/sapporo_density.parquet
```

The processed table contains:

```text
d, t, x, y, count
```

where `count` represents the number of unique individuals observed in a spatial grid cell at a given day and time slot.

The generated parquet file is ignored by Git because it can be reproduced from the raw dataset.

---

## Step 2 — Train ConvLSTM

Run:

```bash
python -m scripts.train_convlstm
```

The training pipeline:

1. Loads `sapporo_density.parquet`
2. Constructs temporal and calendar features
3. Builds historical priors
4. Splits the data into training, validation, and test sets
5. Trains the ConvLSTM model
6. Applies early stopping based on validation performance
7. Saves the trained model

The resulting checkpoint is:

```text
models/convlstm_sapporo.pkl
```

The model checkpoint is ignored by Git because it can be regenerated through the training pipeline.

### Computational Requirements

The full ConvLSTM configuration uses a large training sample and can require substantial computation.

GPU training is recommended.

CPU training may take significantly longer, particularly during ConvLSTM forward and backward passes.

---

## Step 3 — Evaluate ConvLSTM

After training, run:

```bash
python -m scripts.evaluate_convlstm
```

The evaluation script:

1. Reconstructs the same train/validation/test preprocessing pipeline
2. Loads `models/convlstm_sapporo.pkl`
3. Runs prediction on the test set
4. Reports:

```text
RMSE
MAE
R²
```

Because neural-network training can be nondeterministic, independently reproduced metrics may differ from the values reported in the original project presentation.

The purpose of this pipeline is to make the complete data-processing, training, and evaluation procedure reproducible rather than guarantee bit-for-bit identical trained weights.

## Limitations and Future Work

The current implementation is a proof of concept and does not use real-time parking occupancy observations.

Future work includes:

- Integrating real parking-sensor occupancy data
- Calibrating the relationship between predicted mobility flow and actual parking demand
- Incorporating real-time traffic conditions
- Supporting en-route rerouting when parking availability or traffic conditions change
- Evaluating the system with real-world parking occupancy and navigation data
